# 「每日记录」应用设计与功能规格文档

本设计文档详细梳理了「每日记录」(TimeTrackApp) 移动端应用的功能范围、界面设计、数据模型和核心技术特性。应用以优雅现代的 **Material Design 3 (M3)** 为设计核心，基于 Jetpack Compose 构建，旨在帮助用户高效地进行分类时间跟踪和精细化数据分析。

---

## 1. 核心技术栈与架构

*   **架构模式**：MVVM (Model-View-ViewModel) 架构结合响应式状态流。
*   **UI 框架**：100% Kotlin Jetpack Compose。
*   **本地持久化**：Android **Room Room** 多表关联持久化，保障用户数据完全保存在本地，极速响应且离线可用。
*   **异步流传输**：使用 Kotlin Coroutines 与 StateFlow 实现数据的实时响应式刷新。

---

## 2. 页面详细功能规格

### 2.1 计时页 (Timer Screen)
*   **动态跟踪**：一键开启或停止具体时间分类的实时记录。
*   **当月累计与目标进度**：
    *   针对设定的各分类目标（单位：小时），展现当前月的累计执行情况。
    *   **高精度统计算法**：
        1. 累计进度百分比采用 **向下取整 (`floor`)** 算法，提供脚踏实地的目标回馈。
        2. 当前月进度上限强制设为 **100% 封顶**，当超过预定目标时依然保持直观的100%满格成果。
        3. 进度条的长度与百分比严格统一，逻辑完全闭环。

### 2.2 明细页 (History Detail Screen)
*   **极简视觉体验**：去除了原先不必要的分钟数有色标签背景，用无边框的扁平文字展现精细化时间。
*   **单日聚合卡片**：
    *   **改变前**：早期的记录为零散独立卡片，纵向占用大量视觉空间。
    *   **改变后**：**同一天内产生的所有记录，在 UI 上全部聚合在同一个优雅的圆角卡片（Card）内**。
    *   各条记录间使用柔和的 `HorizontalDivider`（透明度0.4）进行优雅划分，极大降低了下滑时的视觉噪音，阅读节奏主次分明。
*   **管理控制**：支持在此页面直接对具体的记录执行单条删除或批量管理操作。

### 3.3 统计页 (Statistics Screen)
*   **多维度分析**：支持以天、周、月为跨度的多图表时间流向跟踪。
*   **无背景纯净进度条**：
    *   在月度分类统计项中，进度条和右侧对应的百分比标签移除了任何多余的外层有色底框或容器背景。
    *   百分比样式与进度线条排列深度紧凑、高密对齐，构成浑然一体的现代极简风。
*   **一致性计算标准**：同样遵循 **向下取整、100%封顶** 的规则，并实时计算生成进度。

## 3. 安全备份机制 (Security & Backup Engine)

为避免用户清理设备存储导致的数据丢失，系统在设置（Settings）模块引入了完整的**应用内本地安全数据备份和恢复系统 (Data Safety Engine)**：

```
 用户数据 (TimeLog) ➔ 序列化为 JSON 字符串 ➔ 生成安全哈希签名 (SHA-256 with Salt) ➔ 保存为 .json 备份文件
```

### 3.1 安全校验与防篡改 (SHA-256 With Salt)
在记录导出时，应用并非简单生成裸 JSON 数据，而是利用特定的混淆盐值进行哈希碰撞签名：
*   **加密算法**：SHA-256 (MessageDigest)
*   **系统内部混淆盐**：`TimeTrackAppSafeBackupSalt_2026`
*   **防伪流程**：将当前所有记录的 `startTime` / `category` / `durationMinutes` 进行全量字段按时间线正序拼接，并追加内部盐，产生绝对唯一的哈希码作为校验值 (`checksum`) 并注入到导出的 JSON 文档中。

### 3.2 强口令恢复导入
*   **一致性校验**：当用户通过 Android 存储框架 (SAF) 触发 `.json` 恢复时，解析引擎会重新算一遍文件内所有记录的当前哈希，如果不和 JSON 文件中的 expected `checksum` 严格吻合，将拒绝反序列化并提示“数据校验失败”，完全防护在传输或手操修改过程中产生的数据污染。
*   **安全性警示**：如果数据校验成功，系统会唤起红色的确定警告窗，在用户最终知悉“导入会覆盖并清空本地所有当前数据”后一键极速重置并写入。

## 4. 数据实体定义

```kotlin
@Entity(tableName = "time_logs")
data class TimeLog(
    @PrimaryKey(autoGenerate = true) val id: Int = 0,
    val category: String,             // 关联时间分类
    val description: String,          // 记录描述（选填）
    val startTime: Long,              // 启动毫秒级时间戳 (UTC/Local)
    val durationMinutes: Long,        // 执行时间 (分钟数)
    val endTime: Long = 0L,           // 截至毫秒级时间戳
    val updatedTime: Long,            // 本条记录更新时间
    val belongDate: String            // 所属日期标识 (yyyy-MM-dd)
)
```
